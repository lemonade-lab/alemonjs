# 应用级强制指令前缀设计

状态：设计草案，尚未实现运行时支持。

## 配置契约

```yaml
apps:
  xiuxian:
    enabled: true
    order: 10
    command:
      prefix: /修仙
      space: false
```

`command` 缺省时完全保留旧行为。配置后，对该应用全部 Router DSL 生效。`space` 缺省为 false；false 生成 `/修仙签到`，true 生成 `/修仙 签到`。这是强制覆盖，不是默认值。应用自身、分组及平台的 routeText 不能绕过它。其他应用保持独立。

prefix 必须为非空字符串且不含空白；space 必须为布尔值。错误配置须报告应用名并阻止该应用加载，不能静默退回旧指令规则。沿用现有模块映射，不改变 enabled/order 和旧数组、布尔配置的兼容行为。

## 输入行为

在通用 parser 删除 `/` 等符号之前，使用应用策略校验原始消息。允许消息外围空白；space=false 要求前缀后直接跟业务指令，space=true 要求一个或多个水平空白，输出统一使用一个 ASCII 空格。只有前缀而没有业务指令时不匹配。

校验通过后只去掉一次完整配置前缀和分隔空白，再交给现有 DSL 的路径、参数、schema 校验。参数内容不得做全局替换。原始消息仍保留给事件和 sourceText，归一化业务指令只存入路由上下文；不能改写共享事件导致其他应用受到影响。

所有 DSL 匹配入口须共用此策略，包括 match、dispatch、handleScopeEvent、适用 scope 筛选，以及 fallback 候选筛选。fallback 不得响应其他应用的前缀。内部 redispatch 必须区分已经解码的业务指令与外部消息，不能二次要求前缀，也不能给外部调用留下绕过入口。

覆盖的是 DSL 指令文本规则。普通事件订阅与任意正则处理器不能靠字符串拼接可靠重写，本设计不声称将其转换成 DSL 指令；它们的处理范围须在实现文档中明确。

## Format 输出行为

输入与输出共用同一份应用策略。对 Button 和 MD.button 中 type 为 command（包括缺省）的 options.data 转换；link、call、rawData、普通文本、URL 不替换。递归处理按钮组、Markdown 及引用块中的结构化指令。

例如 `/签到` 转为 `/修仙签到` 或 `/修仙 签到`，`/背包 2` 保留参数。已是目标前缀的指令只规范分隔符，不能重复添加。替换只识别开头的指令前缀，不切割参数内的 `/`。旧前缀识别应使用路由声明及当前 parser 支持的符号，并按最长前缀优先，不能假设所有旧前缀都只有一个字符。

明确为 command 的无前缀按钮数据按业务指令编码。跨应用按钮不能默认套用当前应用策略，需要显式目标应用标记或退出改写选项，具体 API 在实现时一并确定。

普通按钮标题如“签到”保持原样；框架生成的帮助、参数错误、fallback 建议中的指令使用统一编码函数。任意普通文本无法可靠区分指令与文章内容，建议增加显式指令格式化辅助 API，禁止扫描全文替换斜杠。

优先在消息发送公共管线、平台渲染之前，对结构化消息副本转换，覆盖预先构造的 Format 与嵌套节点，且不污染可复用对象。策略归属取发送时的应用上下文；跨应用消息需要显式目标应用。发送公共管线与所有平台出口的覆盖情况需在实施阶段核实。

## 当前代码依据与修改位置

- `src/common/apps-config.ts`：AppOptions 目前只有 enabled/order；normalizeAppsConfig 最终仅保留 name/enabled/order，新增配置必须贯穿归一化与加载，不能只加类型。

- `src/application/router/dsl.ts`：平台 routeText、scope 筛选和多个匹配入口需要统一接入，避免局部绕过。
- `src/application/router/parser.ts`：目前先去除单字符 !、！、/、#、＃，强制校验必须早于这一步。
- `src/application/format/message-format.ts` 与 `src/types/message/{button,markdown}.ts`：已有 command/link/call 语义，可用来识别指令而不是猜测普通文本。

建议新增内部 command-policy 模块，集中实现配置校验、输入解码和输出编码。DSL 与消息发送管线依赖它，避免互相依赖或维护两套替换规则。应用策略需在重载时刷新，卸载时清理；初版不承诺配置文件修改立即热生效。

## 验收矩阵

| 场景                              | 预期                             |
| --------------------------------- | -------------------------------- |
| 未配置 command                    | 原有匹配和输出保持一致           |
| space=false                       | 接受 /修仙签到，拒绝 /修仙 签到  |
| space=true                        | 接受 /修仙 签到，拒绝 /修仙签到  |
| 旧 /签到、裸签到                  | 配置强制规则后不能命中该应用 DSL |
| 局部分组允许裸指令或另设平台前缀  | 不能绕过应用规则                 |
| 两个应用有相同签到命令            | 按各自前缀隔离，失败提示也隔离   |
| 指令包含参数及参数内斜杠          | 参数不被替换或截断               |
| 嵌套 command 按钮及 Markdown 按钮 | 提交数据使用有效前缀             |
| link、call、普通文字和 URL        | 内容不变                         |
| 已编码指令重复发送                | 不重复前缀，不污染原对象         |
| schema 错误与 fallback 建议       | 展示可以实际发送的完整指令       |
| 非法配置、重载与卸载              | 明确报错，无旧策略残留           |
| 内部 redispatch 与外部 dispatch   | 内部不重复解码，外部不能绕过校验 |
